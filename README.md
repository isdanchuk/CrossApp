# CrossApp

Наскрізний навчальний проєкт з дисципліни «Крос-платформне програмування».

## Предметна область
* **Назва:** Бібліотека
* **Доменні сутності (`Domain`):** `BookCopy` (примірник книги), `Loan` (запис про видачу), `BookReservation` (резервація з enum-станами).
* **Сервіси домену:** `LibraryLoanService` (перевірка міжсутносних інваріантів).
* **Моделі даних (`Dto`):** `BookDto`, `ReaderDto`, `ImportResult<T>` (формати даних з тижня 3).
* **Призначення:** Побудова надійної доменної моделі з чіткими правилами (інваріантами), інкапсуляцією стану та фабричними методами.

## Структура рішення (після Лабораторної №4)
* `src/Core/` — спільна бібліотека бізнес-логіки (не залежить від консолі чи файлової системи):
  * `Dto/` — незмінні `record`-типи для передачі даних.
  * `Domain/` — багата доменна модель (`BookCopy.cs`, `Loan.cs`, `LibraryLoanService.cs`, `BookReservation.cs`) з інкапсуляцією та інваріантами.
  * `Import/` — толерантні парсери даних (з тижня 3).
* `src/Cli/` — консольний застосунок (`Program.cs`), який демонструє два сценарії: успішну роботу та перехоплення винятків під час порушення інваріантів.

## Інваріанти доменної моделі (Лабораторна №4)
Стан сутностей прихований у приватних полях або властивостях із `private set`, публічні конструктори відсутні. Створення можливе лише через статичні фабричні методи (`Create`, `Open`), а зміна стану — через захищені бізнес-методи.

1. **Сутність `BookCopy`:**
   * **Обов'язковість полів:** `Id`, `Isbn` та `Title` не можуть бути порожніми або складатися з пробілів (`ArgumentException`). Під час створення виконується нормалізація (`Trim`, `ToUpperInvariant`).
   * **Заборона повторної видачі:** Не можна викликати `Issue()` для примірника, який уже має статус виданого (`InvalidOperationException`).
   * **Заборона повернення вільного примірника:** Не можна викликати `Return()` для книги, яка не перебуває в оренді (`InvalidOperationException`).

2. **Сутність `Loan` та сервіс `LibraryLoanService`:**
   * Ідентифікатори `LoanId`, `CopyId`, `ReaderId` не можуть бути порожніми (`ArgumentException`).
   * Дата видачі `IssuedAt` не може бути в майбутньому (`ArgumentOutOfRangeException`).
   * **Міжсутносний інваріант (у сервісі):** Не можна відкрити нову видачу для читача, у якого вже є 5 активних відкритих видач (`InvalidOperationException`).

3. **Сутність `BookReservation` (додаткове завдання):**
   * Переходи між станами (`Draft` -> `Active` -> `Closed` / `Cancelled`) суворо контролюються через `switch expression` у методі `ChangeStatus()`. Недопустимий перехід викликає `InvalidOperationException`.
